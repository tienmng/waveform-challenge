These two documents together form a practical guide to building a machine-learning pipeline
that predicts ICU patient deterioration (mortality, hypotension, cardiac arrest) from
high-frequency physiological waveforms.

**Document 1 — Feature engineering.** How to turn raw ECG, ABP, and PPG signals into
model-ready features, typically using sliding windows (5-minute to 24-hour) ahead of a
prediction horizon. ECG: HRV (time/frequency/non-linear), morphology (QRS, ST, QTc), ectopic

morphological surrogates, respiratory/perfusion dynamics. Cross-signal: pulse transit time and
signal quality indices. Recommended tooling: NeuroKit2, BIOBSS, HeartPy; tsfresh; XGBoost/
LightGBM/scikit-learn; SHAP.

**Document 2 — Feature selection.** How to narrow the feature set to the most predictive
signals: filter methods (variance thresholding, mutual information, clinical domain filtering),
wrapper methods (RFE, sequential feature selection), embedded methods (Lasso/L1, tree-based
gain importance), and advanced practices (SHAP for directionality, stability selection via
bootstrapping). Closes with a table mapping each method class to a specific tool.

Both documents end by asking which dataset and prediction window you're using, and whether the
priority is saving compute or maximizing interpretability.

(ABP quarantined from the BP target, QC flags carried, ECG/PPG/PAT-only path in

**Correctness**
- *MAP is estimated when you have the real waveform.* Per-beat MAP was `(sbp + 2*dbp)/3` — a
  cuff estimator. You have the waveform in `beat`, so the true area-under-curve MAP is
  `beat.mean()`. Strictly more accurate, and it flows into `abp_map_lt65_frac` /
  `abp_map_lt60_frac`.
- *SDNN uses population std* (`ddof=0`); HRV convention is sample SD (`ddof=1`).
- *RR filtering then successive differences* — a diff across a dropped beat can inflate
  RMSSD/SDNN slightly.

**Consistency**
- *Two heart rates in the same row.* `hr_bpm` from filtered RR, but `shock_index` recomputes
  HR as a raw peak count. Reuse the filtered-RR HR.
- *PAT foot and peak use different detectors.* Derive both from the same normalized trace.

**Efficiency (matters at ICU volume)**
- `qc.find_rpeaks` ran 3×/segment; `_ppg_norm_and_feet` ran 3×/segment. Compute each once in
  `extract_features` and thread through — the biggest practical win.

**Robustness**
- `find_peaks(-abp, prominence=np.std(abp)*0.3+…)` fails silently on NaNs/flatline. Guard
  finiteness and return NaN when the segment isn't clean.

**When you move to modeling**
- Split by `patient`, not `segment` (`GroupKFold`); bootstrap patients for stability selection.
- Per-target leakage table is correctly encoded — ensure the trainer drops `sbp`/`dbp` and the
  ABP block for the BP target.

**Minor doc nits**
- `ppg_skew`/`ppg_spec_purity` are scalars, not mean/std. Shock-index cutoff 0.9 vs 0.7 across
  docs (0.9 is standard). State that frequency-domain HRV (LF/HF) is *intentionally* excluded

### User
if target is not bp but mortality, why do leakage-aware signal ranking

### Assistant
"Leakage-aware" was never only about the BP envelope. Ranking surfaces whatever correlates
with the label, so it can just as easily hand you leaks for a mortality target — different
leaks, arguably more dangerous and less obvious.

For a BP target the leak is definitional and column-level: `abp_*` *is* the label, so you
exclude those columns. `predictor_columns(df, "outcome")` deliberately does **not** drop
`abp_*`, because for mortality/instability ABP is legitimate physiology. So the protection
moves off the column axis onto the row/window/grouping axes:

- **Patient-identity leakage — the acute one.** Mortality is usually patient-constant: all
  segments of a patient share the label. Features that fingerprint the patient look perfectly
  predictive but generalize nothing — worse than the BP case, where `sbp` varies within a
  patient. Exactly why `stability_selection` bootstraps patients, not rows.
- **Temporal leakage.** Ranking on segments that overlap/follow the event surfaces concurrent
  measurements of dying (hypotension burden, shock index, HRV collapse), not predictors. Feed
  it features from a window that ends before the horizon.
- **Definitional leakage inside "allowed" ABP.** If instability is defined as MAP < 65 for N
  minutes, `abp_map_lt65_frac` basically *is* the label — permitted as a column but circular;
  exclude by hand for that outcome definition.
- **Treatment confounding.** Pressors/fluids move ABP because a clinician anticipated
  deterioration, so the feature can encode the future decision rather than raw state.

So you still rank leakage-aware for mortality: the column guard is a no-op there, but the
patient-grouped bootstrap does real work, and temporal window / definitional ABP / confounding
are on you (no outcome label ships with this dataset).

*Open offer:* add an `outcome`-target guard that optionally drops threshold-defined ABP columns
and requires a `groups` argument, so those protections aren't left to memory.
